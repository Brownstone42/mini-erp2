# Mini-ERP V2 Tech stack

สถานะ: ผู้ใช้ยืนยันการเลือก Next.js เมื่อ 10 พฤศจิกายน 2026 แทนข้อเสนอ Python และ Django ก่อนหน้า

สถานะล่าสุด: ใช้งาน Next.js/TypeScript, Vitest, Playwright, Prisma และ PostgreSQL แล้วตาม R2 เวอร์ชันจริงล็อกใน package.json/package-lock.json PostgreSQL ใช้ local fallback จนกว่า Docker จะพร้อม ส่วน Docker/CI/CD ยังเป็นแผน ดู [ผลตรวจ R2](r2-validation.md)

## รูปแบบแอป

Mini-ERP V2 เป็น Web app เปิดผ่านเบราว์เซอร์ ระหว่างพัฒนาเปิดผ่าน localhost และในอนาคตสามารถรันบนเซิร์ฟเวอร์ให้ Manager เปิดผ่าน URL ภายในบริษัทได้

ใช้ Next.js ดูแลหน้าจอและการทำงานฝั่งเซิร์ฟเวอร์ในโปรเจกต์เดียว แยก logic ธุรกิจ เช่น การรวมยอดรายเดือนและยอดค้างส่ง ออกจากหน้าจอ เพื่อทดสอบได้โดยไม่ต้องเปิดเบราว์เซอร์

## เครื่องมือที่เลือก

| ส่วน | เครื่องมือ | หน้าที่ |
| --- | --- | --- |
| เว็บแอป | Next.js App Router + TypeScript | หน้าจอและการทำงานฝั่งเซิร์ฟเวอร์ |
| หน้าจอ | React + CSS | ตารางข้อมูลและฟอร์มวันทบทวน |
| ฐานข้อมูลของแอป | PostgreSQL | เก็บวันทบทวนและข้อมูลที่แอปต้องจัดเก็บ โดยแยกจาก Express |
| การเข้าถึงฐานข้อมูล | Prisma | อ่านและเขียนฐานข้อมูลของแอป พร้อมจัดการ schema migration |
| ทดสอบกติกาธุรกิจ | Vitest | ตรวจยอด ช่วงเดือน การกรอง และสถานะข้อมูลด้วยข้อมูลสมมติ |
| ทดสอบผ่านเบราว์เซอร์ | Playwright | ตรวจข้อมูลที่ Manager เห็นและการบันทึกผ่านหน้าจอ |
| ตรวจคุณภาพโค้ด | TypeScript type check + ESLint | ตรวจชนิดข้อมูลและข้อผิดพลาดพื้นฐาน |
| รันและ deploy | Docker + Docker Compose | รันแอปและฐานข้อมูลให้ทำซ้ำได้ |
| CI/CD | GitHub Actions + Container Registry | ตรวจโค้ด ทดสอบ สร้างและเก็บ image แต่ละรุ่น |

เวอร์ชัน Next.js, Node.js และ dependencies ที่แน่นอนจะเลือกให้เข้ากันและล็อกเมื่อเริ่มตั้งโปรเจกต์ ยังไม่ได้เลือกผู้ให้บริการ Container Registry หรือเครื่องปลายทางในรอบนี้

## การแยกข้อมูล

- ข้อมูลสินค้า คลัง บริษัทลูกค้า รายการส่งจริง ยอดค้างส่ง ยอดคงเหลือ MOQ และ lead time เริ่มจากชุดข้อมูลสมมติที่กำหนดตายตัว
- วันกลับมาทบทวนที่ Manager บันทึก เก็บใน PostgreSQL ของแอป
- แยกส่วนอ่านข้อมูลออกจาก logic ธุรกิจ เพื่อเปลี่ยนแหล่งข้อมูลภายหลังโดยใช้กติกาและหน้าจอเดิม
- แยกรายการส่งจริงออกจากยอดค้างส่ง พร้อมเวลาอ้างอิงและสถานะความพร้อมของข้อมูล เพื่อไม่สับสนระหว่างข้อมูลขาดกับยอดเป็นศูนย์

รอบพัฒนาด้วยข้อมูลสมมติยังไม่ติดตั้งตัวอ่าน DBF และไม่เข้าถึง `Y:\IG60` การเชื่อม Express เป็นงานรอบถัดไป โดยต้องอ่านอย่างเดียวและยืนยันกติกาข้อมูลก่อน

## เหตุผลและข้อแลกเปลี่ยน

ผู้ใช้ต้องการฝึก Next.js จึงใช้ TypeScript สำหรับหน้าจอ การทำงานฝั่งเซิร์ฟเวอร์ และการทดสอบ การเริ่มจากหน้าเดียวช่วยให้เรียนรู้ React และการแบ่งงานระหว่าง browser กับ server ตามความจำเป็น

สามารถรัน Next.js บน Node.js หรือ Docker ได้ จึงใช้ฝึก deploy และ rollback โดยไม่ผูกกับ Vercel ตาม [เอกสาร Next.js Self-hosting](https://nextjs.org/docs/app/guides/self-hosting)
