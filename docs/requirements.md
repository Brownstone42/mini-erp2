# Mini-ERP V2 Requirement — ยอดสั่งรายเดือนและค้างส่งรวม

ฉบับ R2 — ผู้ใช้ยืนยันและอนุมัติให้ทำ AT ทุกกรณีแล้ว

แอปและ automated tests ปรับเป็นยอดสั่งรายเดือน รายงานค้างส่งแยกแหล่ง และหน้ารายละเอียดด้วยข้อมูลสมมติแล้ว ไม่เชื่อม DBF และไม่ทำ Docker ดู [ผลตรวจ R2](r2-validation.md) และ [ฉบับเดิม R1](history/requirements-v1.md)

## เป้าหมายและขอบเขต

Manager ดูความต้องการซื้อจากยอดสั่งรายเดือนและภาระที่ยังต้องส่งจากยอดค้างส่งรวม พร้อมคงเหลือ MOQ และ lead time เพื่อตัดสินใจเติมสต็อกด้วยตนเองและตั้งวันกลับมาทบทวน

เริ่มจากถุงมือ Vinyl หนึ่ง SKU บริษัทมีคลังเดียว ไม่ต้องเลือกคลัง แยกยอดตามคลัง หรือรองรับหลายคลังในรอบนี้ หาก Express มีรหัสคลัง ให้ตรวจ mapping ของคลังที่ใช้งานภายหลัง ไม่เพิ่มตัวเลือกคลังให้ Manager

## ความหมายของข้อมูล

- บริษัทในตารางหมายถึงบริษัทลูกค้า ใช้รหัสลูกค้าจับคู่ ไม่ใช้ชื่อเป็นตัวเชื่อม
- ยอดสั่งรายเดือน: จำนวนสินค้าที่ลูกค้าสั่งตามเอกสารคำสั่งซื้อ จัดเดือนตามวันที่สั่ง/วันที่เอกสารคำสั่งซื้อ ไม่ใช่วันที่ส่งจริงหรือกำหนดส่ง
- ช่วงตาราง: เดือนปัจจุบันรวมย้อนหลัง 11 เดือน เดือนปัจจุบันเป็นข้อมูลถึงเวลาอ้างอิงของ snapshot ไม่ใช่เต็มเดือน
- ยอดค้างส่งรวม: ยอดของ SKU นี้ตามรายงานค้างส่ง Express ณ เวลาอ้างอิง ไม่จำกัดด้วยช่วงตาราง วันที่สั่ง หรือกำหนดส่ง รวมงานเก่าเกิน 12 เดือนและงานจองล่วงหน้าที่อยู่ในรายงานนั้น
- งานจองล่วงหน้าเป็นงานที่มีอยู่ใน snapshot แล้วแต่กำหนดส่งในอนาคต ไม่ใช่ข้อมูลที่จะเกิดขึ้นหลัง snapshot
- ยอดส่งจริง: จำนวนที่ส่งมอบแล้ว ใช้ในหน้ารายละเอียดเปรียบเทียบคำสั่งซื้อ ไม่ใช่ยอดหลักบนหน้าทบทวน

ตัวอย่าง สั่ง พ.ย. 2026 กำหนดส่ง ม.ค. 2027: ยอดสั่งอยู่ พ.ย. และยอดที่ค้างรวมอยู่ในค้างส่งหากรายงาน Express ระบุไว้ ไม่ย้ายยอดสั่งไป ม.ค.

## หน้าหลัก

| ID | ข้อกำหนด R2 |
| --- | --- |
| REQ-01 | ทุกยอดเป็นของ SKU ที่กำหนด ในกิจการคลังเดียว ไม่มีตัวเลือกคลังหรือตารางแยกคลัง |
| REQ-02 | แสดงหน่วยกล่องชัดเจน ข้อมูลสมมติใช้หน่วยเดียวทั้งหมด |
| REQ-03 | แสดงยอดคงเหลือตามแหล่งข้อมูลพร้อมวันเวลา ไม่หักค้างส่งออกเอง |
| REQ-04 | ตารางยอดสั่งครบ 12 เดือนแยกบริษัท มีรวมแต่ละบริษัทตลอดช่วง แถวรวมทุกบริษัทแยกเดือน และยอดสั่งรวมตลอดช่วง การ์ดสรุปยอดสั่งตรงกับตาราง |
| REQ-05 | แสดงการ์ดยอดค้างส่งรวมตามรายงาน Express ไม่จำกัดช่วงเวลา ไม่ใส่คอลัมน์ค้างส่งแยกบริษัทในตารางหลัก |
| REQ-06 | ยอดสั่งไม่เปลี่ยนเพียงเพราะส่งหลายครั้ง ไม่บวกซ้ำตามจำนวนใบส่ง และไม่บวกยอดสั่งกับค้างส่งเป็นความต้องการรวม เพราะอาจนับซ้ำ |
| REQ-07 | เดือนที่ข้อมูลครบแต่ไม่มียอดสั่งแสดง 0 มีครบ 12 เดือน ระบุเดือนปัจจุบันยังไม่เต็มเดือน |
| REQ-08 | แสดง MOQ / lead time พร้อมหน่วย Manager ตัดสินใจเอง ไม่สร้างคำสั่งซื้ออัตโนมัติ |
| REQ-09 | ตั้งและเปลี่ยนวันทบทวนได้ บันทึกแล้วเปิดหน้าใหม่ยังเห็นวันที่ล่าสุด |
| REQ-10 | แยกสถานะคงเหลือ ยอดสั่ง และค้างส่ง พร้อมเวลาข้อมูลแต่ละส่วน ข้อมูลขาดแสดง — / ข้อมูลไม่พร้อม ไม่แทนด้วย 0 หรือคำนวณทดแทน หากยังไม่เทียบ Express ให้ระบุว่ายังไม่ยืนยัน |

หน้าหลักไม่มีตารางส่งจริง รายการเอกสารรายใบ หรือรายละเอียดค้างส่งรายบริษัท/รายวัน ให้เปิดหน้ารายละเอียดเมื่อต้องการ

| ID | ข้อกำหนด R2 |
| --- | --- |
| REQ-11 | เปิดรายละเอียดจากค้างส่งรวมได้ เห็นบริษัท เอกสารอ้างอิง จำนวนค้าง วันที่สั่ง และกำหนดส่งเมื่อแหล่งข้อมูลมีให้ แยกชื่อวันที่ชัด รวมงานเก่าและงานจอง ยอดรวมตรงหน้าหลักสำหรับ SKU และ snapshot เดียวกัน |

หน้ารายละเอียดค้างส่งและคำสั่งซื้อเทียบส่งจริงรองรับด้วยข้อมูลสมมติแล้วตามการอนุมัติ R2

## แหล่งข้อมูลและเรื่องที่ต้องยืนยัน

ค้างส่งใช้รายงาน Express เป็นหลัก ไม่ตั้งสูตรสั่งลบส่งแทนรายงาน ถ้ามีค้างเป็นรายรายการให้รวมจำนวนค้างของ SKU ได้ ถ้ามียอดสรุปให้ใช้และเทียบรายละเอียด โดยไม่บวกยอดสรุปซ้ำกับรายการ

ยังไม่เรียกยอดสั่งว่า “ยอดสั่งสุทธิ” หรือกำหนดสูตรหักยกเลิก/คืนเอง ชุดสมมติไม่มีการยกเลิก คืน หรือปิดรายการ ต้องยืนยันกติกาให้ตรง Express ก่อนใช้ข้อมูลจริง

แหล่งจริงคือ DBF ที่ `Y:\IG60` ต้องอ่านอย่างเดียว วันทบทวนเก็บในฐานแอปแยกจาก Express รอบนี้ไม่เข้าถึง DBF

ต้องตรวจต่อในรอบข้อมูลจริง:

- เอกสาร/ฟิลด์ที่เป็นคำสั่งซื้อและวันที่สั่ง ไม่ถือว่า SO หรือ Invoice ยืนยันการส่งจริงเพียงเพราะชื่อ
- เอกสาร/ฟิลด์การส่งจริง และความสัมพันธ์กับรายการสั่ง
- รายงานค้างส่งและตัวกรองที่ใช้เทียบ รวมงานเก่า งานจอง ยกเลิก และปิดรายการอย่างไร
- ความหมายวันที่แต่ละชนิด หน่วยสินค้า คงเหลือ และ mapping คลังเดียว
- เทียบยอดสั่ง คงเหลือ และค้างส่งกับ Express ในรอบเวลาและขอบเขตเดียวกันก่อนระบุว่ายืนยันแล้ว
- แหล่งที่มาและผู้แก้ไข MOQ / lead time

ผู้ใช้แจ้งว่าเคยพบรหัสลูกค้าในข้อมูลค้างส่งที่เชื่อมประวัติส่งขายได้ แต่ยังไม่ใช่การยืนยัน mapping และยอดจริงทั้งหมด

ไม่รวมการแนะนำจำนวนสั่งซื้ออัตโนมัติ การสร้างใบสั่งซื้อ การเขียนกลับ Express และการรองรับหลายคลัง ดู [Acceptance tests R2](acceptance-tests.md)
