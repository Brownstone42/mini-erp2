# ผลตรวจ R2 — ข้อมูลสมมติ

ครอบคลุม AT-R2-01 ถึง AT-R2-20 ตามเอกสารที่ผู้ใช้ยืนยัน ดู [เกณฑ์ตรวจรับ](acceptance-tests.md)

## สิ่งที่เปลี่ยน

- `review-demand.ts` จัดเดือนตามวันที่สั่งและแยก snapshot คงเหลือ/คำสั่งซื้อ/รายงานค้างออกจากกัน
- `demo-demand.ts` ให้รายการสมมติและรายงานค้างที่เป็น input อิสระ ไม่คำนวณค้างจากสั่งลบส่ง
- หน้าหลักใช้ตารางยอดสั่ง ไม่มีคอลัมน์ส่งจริงหรือค้างรายบริษัท ไม่มีตัวเลือกคลัง
- `/outstanding` แสดงรายงานค้างทุกอายุพร้อมวันที่สั่ง/กำหนดส่ง
- `/orders/[customerCode]` แสดงคำสั่งซื้อในช่วงตารางและรายการส่งของคำสั่งเหล่านั้นถึง snapshot
- ลิงก์กลับเก็บ scenario เดิม จึงไม่เปลี่ยนชุดข้อมูลเมื่อเปิดรายละเอียดแล้วกลับมา
- เก็บ tests logic R1 ไว้ ส่วน browser tests ที่ข้อกำหนดเปลี่ยนปรับเป็น R2 การบันทึกวันและ MOQ เดิมใช้ต่อพร้อมระบุรหัส R2

## Red → Green

ก่อนเขียน logic: `npx vitest run tests/acceptance/r2.test.ts` ล้มเหลว 18 tests ด้วยข้อความว่าการรวมยอดสั่งและรายงานค้างยังไม่ implement หลังเพิ่ม logic ผ่านทั้ง 18 tests โดยค่าคาดหวังเดิม

ก่อนแก้หน้า: browser tests ตารางใหม่ล้มเหลว 3 ข้อ (หยุดเมื่อครบ 3 failures) เพราะยังเป็นตารางส่งจริงและไม่มีพฤติกรรม R2 และ tests รายละเอียด AT-R2-18/19 ล้มเหลวอีก 2 ข้อ เพราะไม่มีลิงก์เปิดหน้ารายละเอียด

หลังเพิ่มหน้าและ logic: การรันทั้งชุดพบ test หนึ่งตรวจป้ายสถานะก่อน Next.js เปลี่ยนหน้าเสร็จ จึงเจอป้ายสองแห่งบนหน้าหลัก แก้ test ให้รอ heading หน้ารายละเอียดก่อนตรวจสถานะ ไม่เปลี่ยนผลคาดหวังธุรกิจ

ใช้ข้อมูลสมมติทั้งหมด ยังไม่ยืนยันเอกสาร/ฟิลด์ DBF หรือกติกายกเลิก คืน ปิดรายการจริง ข้อมูลรายวันต้องมาจาก snapshot ที่คัดรายการถึงเวลาที่กำหนดแล้ว การเทียบยอด Express ยังไม่ได้ทำ

วันทบทวนทดสอบบน PostgreSQL แยกจากฐานพัฒนา คีย์คลังเดิมคงอยู่ภายในฐานเพื่อไม่กระทบข้อมูลเดิม ไม่มี UI หรือความสามารถแยกคลังใน R2 ไม่มีการรัน Docker หรือ migration ใหม่ในรอบนี้
