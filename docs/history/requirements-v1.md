# Mini-ERP V2 Requirement หน้าทบทวนการเติมสต็อก

สถานะ: ผู้ใช้ยืนยัน requirement และ acceptance test เมื่อ 10 พฤศจิกายน 2026

ขั้นตอนปัจจุบัน: บันทึกเอกสารด้วยข้อมูลสมมติเท่านั้น ยังไม่เริ่มเขียนโค้ด เชื่อม DBF ทำ Docker, CI/CD, deploy หรือ rollback

## เป้าหมาย

Manager ใช้หน้าทบทวนการเติมสต็อกเพื่อดูยอดคงเหลือ ยอดส่งจริง และยอดค้างส่ง พร้อม MOQ และ lead time แล้วตัดสินใจเติมสต็อกด้วยตนเอง และตั้งวันที่กลับมาทบทวนได้

เริ่มจากถุงมือ Vinyl หนึ่ง SKU และหนึ่งคลัง โครงการนี้ใช้ฝึกกระบวนการพัฒนาตั้งแต่ requirement และ acceptance test ไปจนถึง Docker, CI/CD, deploy และ rollback ในขั้นตอนภายหลัง

## คำจำกัดความที่ยืนยันแล้ว

- บริษัท หมายถึงบริษัทลูกค้า ใช้รหัสลูกค้าเชื่อมข้อมูล ไม่ใช้ชื่อบริษัทในการจับคู่
- ย้อนหลัง 12 เดือน หมายถึงเดือนปัจจุบันรวมย้อนหลังอีก 11 เดือน โดยระบุว่าเดือนปัจจุบันยังไม่ครบเดือน
- ยอดส่งจริง หมายถึงจำนวนที่ส่งสินค้าจริงตามวันที่ส่ง ไม่ใช่จำนวนที่ลูกค้าสั่ง
- ยอดค้างส่ง หมายถึงจำนวนที่ยังมีภาระต้องส่ง ณ เวลาของข้อมูล รวมคำสั่งซื้อเก่าที่อยู่นอกช่วงรายงาน 12 เดือน

## Requirement

| ID | ข้อกำหนด |
| --- | --- |
| REQ-01 | ทุกยอดต้องเป็นของ SKU และคลังที่กำหนดเท่านั้น |
| REQ-02 | แสดงหน่วยเป็นกล่องทุกส่วน ข้อมูลสมมติใช้หน่วยเดียวกันทั้งหมด |
| REQ-03 | แสดงยอดคงเหลือตามแหล่งข้อมูล พร้อมวันและเวลาของข้อมูล ไม่หักยอดค้างส่งออกเอง |
| REQ-04 | แสดงยอดส่งจริงย้อนหลัง 12 เดือน แยกเดือนและบริษัทลูกค้า พร้อมยอดรวม |
| REQ-05 | แสดงยอดค้างส่งปัจจุบันแยกบริษัทลูกค้า พร้อมยอดรวม โดยไม่จำกัดอายุคำสั่งซื้อไว้ที่ 12 เดือน |
| REQ-06 | แยกยอดส่งจริงและยอดค้างส่ง ห้ามนำยอดสั่งทั้งหมดไปนับเป็นยอดส่งจริง และห้ามนับซ้ำเมื่อมีการส่งหลายครั้ง |
| REQ-07 | แสดงเดือนครบ 12 เดือน เดือนที่ข้อมูลครบแต่ไม่มีการส่งให้แสดง 0 หากข้อมูลขาดให้แสดงว่าข้อมูลไม่พร้อม |
| REQ-08 | แสดง MOQ และ lead time พร้อมหน่วย เพื่อให้ Manager ตัดสินใจเอง |
| REQ-09 | Manager ตั้งและเปลี่ยนวันกลับมาทบทวนได้ บันทึกแล้วเปิดหน้าใหม่ยังเห็นวันที่ที่บันทึกไว้ |
| REQ-10 | แสดงสถานะข้อมูลที่ไม่พร้อมหรือยังไม่ผ่านการยืนยันอย่างชัดเจน ไม่แทนข้อมูลขาดด้วย 0 และไม่แสดงว่าได้รับการยืนยันแล้ว |

## ตัวอย่างหลัก

ลูกค้าสั่ง 100 กล่อง ส่งแล้ว 60 กล่อง และไม่มีการยกเลิก ระบบต้องแสดงยอดส่งจริง 60 กล่อง และยอดค้างส่ง 40 กล่องแยกกัน

ชุดข้อมูลสมมติและกรณีตรวจรับทั้งหมดอยู่ใน [Acceptance tests](acceptance-tests.md)

## ขอบเขตที่ยังไม่รวม

- การคำนวณจำนวนสั่งซื้อที่แนะนำ
- การสร้างใบสั่งซื้อหรือสั่งซื้ออัตโนมัติ
- การเขียนข้อมูลกลับเข้า Express

## ข้อมูลจริงและเงื่อนไขก่อนใช้งาน

แหล่งข้อมูลจริงคือ DBF ของ Express ที่ `Y:\IG60` ต้องเข้าถึงแบบอ่านอย่างเดียว ข้อมูลที่แอปบันทึกเอง เช่น วันทบทวน ต้องเก็บแยกจาก Express

ตามข้อมูลที่ผู้ใช้แจ้ง เคยตรวจแล้วว่าข้อมูลค้างส่งมีรหัสลูกค้าเชื่อมกับประวัติส่งขายได้ ส่วนยอดคงเหลือและยอดค้างส่งยังต้องเทียบกับ Express ในรอบเวลาเดียวกันก่อนถือว่าได้รับการยืนยัน

ประเด็นที่ต้องตกลงและตรวจสอบก่อนตรวจรับด้วยข้อมูลจริง:

- ฟิลด์และเอกสารใดถือเป็นยอดส่งจริง รวมถึงวิธีจัดการคืนสินค้าและเอกสารยกเลิก
- วิธีคำนวณยอดค้างเมื่อยกเลิกบางส่วนหรือปิดคำสั่งซื้อ
- ความหมายของยอดคงเหลือ หน่วยสินค้า และการระบุคลัง
- วิธีเทียบยอดคงเหลือและยอดค้างส่งกับ Express โดยใช้ข้อมูลในรอบเวลาเดียวกัน
- แหล่งที่มาและผู้แก้ไข MOQ กับ lead time

การยืนยันเอกสารนี้เป็นการยืนยันพฤติกรรมที่ต้องการด้วยข้อมูลสมมติ ยังไม่ใช่การยืนยันความถูกต้องของข้อมูลจริงหรืออนุญาตให้เริ่มเขียนโค้ดในรอบนี้
