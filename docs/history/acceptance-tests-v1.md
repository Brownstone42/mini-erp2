# Mini-ERP V2 Acceptance tests หน้าทบทวนการเติมสต็อก

สถานะ ณ 10 พฤศจิกายน 2026: AT-01 ถึง AT-10 ผ่านระดับ logic ด้วย Vitest รวม 22 tests และ AT-14 เพิ่ม 5 tests สำหรับสถานะข้อมูล AT-11 ถึง AT-14 มี Playwright/Chromium 9 tests และเพิ่ม browser tests ตารางอีก 4 tests หน้าเว็บมีการ์ดและตารางยอดรายเดือนแยกบริษัทจาก logic เดิม พร้อมสถานะข้อมูล และบันทึก/เปลี่ยนวันทบทวนใน PostgreSQL ได้ สินค้าและยอดยังเป็นข้อมูลสมมติ ไม่มีการเชื่อม Express ดูวิธีรัน ผล และข้อจำกัดใน [README](../README.md)

อ้างอิง [Requirement](requirements.md) บริษัทหมายถึงบริษัทลูกค้า และช่วงรายงานคือเดือนปัจจุบันรวมย้อนหลัง 11 เดือน

## ข้อจำกัดการตรวจรับ

AT-14 ตรวจข้อมูลขาดแยกยอดคงเหลือ ยอดส่งจริง และยอดค้างส่ง: ต้องแสดง “— / ข้อมูลไม่พร้อม” พร้อมเหตุผล โดยส่วนที่พร้อมยังแสดงได้ ตัวเลข 0 ต้องคงเป็น 0 ส่วนตัวเลขที่ยังไม่เทียบ Express ต้องแสดง “ยังไม่ยืนยันกับ Express” พร้อมเวลาข้อมูล ไม่มีการแทน null ด้วย 0 และแม้มี flag ยืนยันค้างมาก็ต้องไม่ยืนยันเมื่อข้อมูลขาด การ์ดและตารางใช้ผลคำนวณชุดสมมติเดียวกันและจำลองสถานะขาดแยกส่วน ยังไม่ใช่ผลจาก connector จริง

`tests/e2e/customer-table.spec.ts` ตรวจชุดตัวอย่างหลักบนหน้าเว็บ: ทั้ง 12 เดือนของ C001/C002 และแถวรวมต้องตรงตามตารางข้างต้น การ์ดต้องตรงกับยอดรวม ตารางต้องแสดงสถานะไม่ยืนยันและเวลาข้อมูล เมื่อข้อมูลส่งหรือค้างขาดต้องแสดง — ทั้งรายละเอียดและแถวรวมเฉพาะส่วนนั้น รวมถึงตรวจมือถือว่าเลื่อนตารางได้โดยหน้าไม่ล้น กรณีขอบเขตวันที่ คำสั่งซื้อเก่า และสินค้า/คลังอื่นยังตรวจระดับ logic ตาม AT เดิม

การตรวจรับด้วยข้อมูลสมมติยังไม่ยืนยัน mapping ฟิลด์ DBF หรือความถูกต้องของยอดใน Express ประเด็นคืนสินค้า ยกเลิกเอกสาร ปิดคำสั่งซื้อ หน่วยสินค้า และการเทียบยอดในรอบเวลาเดียวกันต้องได้ข้อสรุปตาม requirement ก่อนเพิ่มกรณีตรวจรับข้อมูลจริง
